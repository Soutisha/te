00 / DATA PROVENANCE

What is real, what is simulated.

Operational data arrives through a read-only telemetry feed. Today that feed is a built-in synthetic generator (from the sample CSVs), not a real dealership, and the Living World streams a local simulation.

Why synthetic: a real feed needs a dealership’s authorised read-only endpoint, credentials and response schema, which this project does not have. So the adapter reads the synthetic feed and labels it SIMULATED. To use a real one, set TELEMETRY_URL (and TELEMETRY_TOKEN); it is shown LIVE only after a successful, schema-validated call, and a failed call shows ERROR instead of falling back to synthetic data.

Why these numbers are synthetic: the models are trained on generated demand history, so every score (F1, savings, resolution time) measures how well they learn the generator, not real dealerships. Why federated learning is not private: it runs FedAvg in a single process. Each dealer’s weights are sent as plain numbers and averaged, with no secure aggregation (so the server could read each dealer’s update) and no differential privacy (no noise limiting what a weight leaks), and the shared normalisation reveals aggregate statistics. It shows that raw rows need not move, not that the updates are confidential.
